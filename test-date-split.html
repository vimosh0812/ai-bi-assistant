Expected Results (Improved Detection)

The following columns should be detected as date columns and split:

  • Birth Date - Various formats (YYYY-MM-DD, MM/DD/YYYY, DD.MM.YYYY, Month DD, YYYY, DD Month YYYY)
  • Created At - DateTime format (YYYY-MM-DD HH:mm:ss)
  • Start Date - DD/MM/YYYY format (23/07/2019, 05/03/2020, etc.)
  • End Date - DD/MM/YYYY format (15/12/2023, 28/11/2024, etc.)
  • Updated At - DD-MM-YYYY format (12-11-2019, 08-03-2020, etc.)
  • Last Login - UTC DateTime format (2024-01-15T10:30:00Z, 2024-02-20T14:45:00.000Z, etc.)

The following columns should NOT be detected as date columns (improved filtering):

  • Year Only - Single year values (2024) - too ambiguous, could be product years, model years, etc.
  • Month Year - Month Year format (March 2024) - too ambiguous, could be publication dates, etc.
  • Invalid Date - Contains non-date values

New Conservative Rules:

  • ✅ Requires 80% pattern matching AND 70% valid date parsing
  • ✅ Excludes columns with names like "id", "number", "code", "version", etc.
  • ✅ Excludes patterns that look like phone numbers, SSNs, version numbers
  • ✅ Requires minimum 8 characters for date strings
  • ✅ Year range validation (1900-2100)
  • ✅ Requires month names or specific date structure for ambiguous cases

Expected Split Columns

For each detected date column, three new columns should be created:

  • column_name_year - Contains the year (number)
  • column_name_month - Contains the month (number 1-12)
  • column_name_day - Contains the day (number 1-31, null if not available)
